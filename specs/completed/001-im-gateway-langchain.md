# SPEC-001：IM Gateway 与 LangChain 迁移

## 范围

将飞书消息收发与模型执行拆分为独立进程。统一消息包含平台、账号、消息、会话、用户标识与正文。网关使用本机 HTTP、Bearer 认证与 NDJSON 流式事件；模型路由保留 API、Codex、auto 和既有指令。将旧 Agently 聊天和工具循环迁到 LangChain，保留时间、计算工具。

## 验收

- 飞书命令保持一次性回复；普通对话保持同卡片流式更新。
- HTTP snapshot 在生成结束前到达；断流不可当作成功。
- 平台、账号、会话和用户隔离；默认飞书键兼容已有数据。
- 同编号请求只生成一次，终态跨进程重启可回放；编号冲突拒绝执行。
- 非正常中断的任务明确报错，不自动重新生成或切换模型。
- 请求鉴权、输入验证、容量限制、仅本机绑定。
- 正常停机等待正在执行的请求结束。
- 网关无飞书凭据也可启动；运行代码与依赖不再使用 Agently。
- 完整运行项目全量回归并通过。

## 测试关联

新增 tests/test_gateway.py；现有 test_dispatch.py、test_codex.py、test_model_routing.py、test_streaming.py、test_lifecycle.py 全量回归。

## 边界

本次实现飞书桥接及通用网关客户端。企微真实回调、解密和发送接口不在本次范围。生成去重不等于 IM 投递恰好一次；断电后自动补发与发送队列不在本次范围。状态及结果由独立索引维护，spec 原文不回写。
